# Stream Post

Веб-платформа для создания профессиональных публикаций в Telegram для киберспортивных стримеров MLBB.

**Статус:** v0.6.1. Один редактор готовит **три типа поста** MLBB (страница `#/schedule`): расписание матчей, предикты стримера и итоги дня. Для каждого — картинка **и текстовая подпись** к ней. «Предикты» и «Итоги дня» получили собственный постер-дизайн: крупный наклонный заголовок, подзаголовок, симметричные карточки матчей с логотипами, коэффициентами и акцентной плашкой счёта. В футере итогов — SVG-иконка Telegram и ссылка на канал. Добавлены библиотека логотипов команд с сохранением на устройстве и интерфейс, заточенный под телефон. Картинка рисуется прямо в браузере (canvas), текст собирается из тех же данных — backend для этого не нужен. **Пока проект только готовит материалы для поста** — подключение к Telegram и отправка постов напрямую появятся позже.

## Что умеет

- Ручной ввод турнира, даты, стадии, таймзоны, ссылки на стрим, **Telegram-канала** и списка матчей (до 8, форматы BO1–BO7).
- **Логотипы команд**: загрузка PNG/JPG/WEBP/SVG из галереи телефона, автосжатие до 320 px, постоянное хранение в IndexedDB (с fallback на localStorage). Логотип автоматически подставляется в матч, если название команды совпадает с названием логотипа; при необходимости можно выбрать логотип вручную прямо в карточке матча.
- Три формата поста: 4:5 (1080×1350), квадрат (1080×1080), сторис 9:16 (1080×1920) и четыре цветовые темы.
- Экспорт готового PNG: системное меню «Поделиться» (на iPhone — «Сохранить в Фото»), скачивание файла или долгое нажатие на предпросмотр.
- **Текст поста** по шаблону с разделителями: турнир, стадия, дата, список матчей, ссылка на стрим и концовка. Собирается автоматически из тех же данных, что и картинка; итоговый текст можно отредактировать перед копированием или посмотреть в оформленном превью.
- **Три типа поста** (расписание / предикты / итоги дня) используют одни и те же матчи и логотипы. Расписание осталось в классической вёрстке; предикты и итоги рисуются отдельным постер-рендером.
- **Коэффициенты на победу** (`1.48`, `2.62`) вводятся на матч и показываются в боковых плашках на картинке предиктов. Прогноз счёта задаётся отдельно, рисуется в центральной акцентной плашке **и** уходит в текст поста.
- **Telegram-канал** задаётся отдельно от ссылки на стрим: в футере «Итогов дня» рисуются настоящий SVG-контур логотипа Telegram (через `Path2D`) и ссылка `t.me/…`.
- Черновик поста, оба счёта, коэффициенты, обе ссылки, логотипы, настройки текста и ручная правка сохраняются в браузере — после перезагрузки ничего не теряется.

## Типы поста

Переключатель **«Расписание / Предикты / Итоги дня»** над заголовком страницы (или ссылки с главной: `#/schedule?mode=predict`, `#/schedule?mode=results`) меняет картинку и подпись, но не трогает введённые матчи. У каждого матча два независимых счёта (прогноз и финальный результат, по одной цифре `0–9` на команду) и, в предиктах, пара коэффициентов.

| Режим | Дизайн картинки | Плашки под командами | Строка в тексте | Имя файла |
| --- | --- | --- | --- | --- |
| Расписание | Классическая вёрстка: время, формат BO, `VS` в центре | — | `09:00 — NAVI vs AE (BO5)` | `mlbb-2026-11-05.png` |
| Предикты | Постер «ПРЕДИКТЫ НА ДЕНЬ», подзаголовок «Кто победит сегодня?», футер с призывом к комментариям | Три симметричные плашки: `1.48` · **`2 : 1`** · `2.62` — центр с прогнозом счёта залит акцентом (не заполнен → `—` / `? : ?`) | `09:00 — NAVI vs AE (BO5) · прогноз 2:1` | `mlbb-2026-11-05-predict.png` |
| Итоги дня | Постер «ИТОГ ДНЯ», подзаголовок «Как прошёл игровой день?», футер с SVG-иконкой Telegram и ссылкой `t.me/…` | Один крупный бейдж `2 : 1` строго по центру с подписью «BO5 · ФИНАЛЬНЫЙ СЧЁТ»; победитель подсвечен, проигравший приглушён | `09:00 — NAVI 2:1 AE (BO5)` | `mlbb-2026-11-05-results.png` |

Оба постера строятся общим конвейером `render/renderPoster.ts`: наклонный жирный заголовок (эмулируется наклоном canvas без отдельного начертания шрифта, с компенсацией сдвига по центру строки), акцентная черта и симметричная сетка карточек. У каждой карточки две горизонтали: сверху — круглый слот логотипа, название, центральный якорь (`vs` в предиктах / время в итогах), зеркальное название и слот; снизу — три колонки значений по единой оси. Слоты рисуются всегда, даже без логотипа, поэтому левая и правая зоны совпадают при любых данных. Расписание рисуется старым конвейером `renderSchedule` и не затронуто. Пресеты (4:5, квадрат, сторис), темы, логотипы, адаптация под 2–8 матчей и экспорт PNG работают одинаково во всех режимах. Прогнозы, коэффициенты и финальные счета хранятся раздельно: введение итогов не затирает предикты.

## Текст поста

Вкладка **«Текст»** (`#/schedule?tab=text`) собирает подпись к фотографии:

```text
🏆 {{TOURNAMENT_NAME}}

━━━━━━━━━━━━━━━━━━

⚔️ {{STAGE}}
📅 {{DATE}}

РАСПИСАНИЕ МАТЧЕЙ

{{MATCH_LIST}}

━━━━━━━━━━━━━━━━━━

📺 ТРАНСЛЯЦИЯ
{{STREAM LINK}}

🔥 До встречи на трансляции!
```

`{{MATCH_LIST}}` — по одной строке на каждый заполненный матч: `09:00 — NAVI vs AE (BO5)`. Пустые карточки матчей пропускаются, время приводится к `HH:MM`, незаполненная команда заменяется на `TBD`. Если стадия не заполнена, строка `⚔️ {{STAGE}}` убирается целиком. Плейсхолдер ссылки понимает оба написания — `{{STREAM LINK}}` и `{{STREAM_LINK}}`.

**Подпись зависит от режима.** Структура шаблона и разделители остаются прежними, меняются заголовок секции (`РАСПИСАНИЕ МАТЧЕЙ` → `ПРОГНОЗЫ НА МАТЧИ` / `РЕЗУЛЬТАТЫ МАТЧЕЙ`) и строки матчей: в предикты добавляется `· прогноз 2:1`, в итогах `vs` заменяется финальным счётом. Ручная правка привязана к режиму и счётам — переключение или изменение счёта показывает предупреждение, а не подменяет текст молча. Прогноз счёта влияет и на текст, и на картинку; правка коэффициентов на текст не влияет и правку не сбрасывает.

В панели есть переключатель **«Правка / Превью»**: превью показывает ту же подпись оформленной карточкой в стиле сообщения Telegram (акцентные разделители, заголовки, время матчей моноширинным шрифтом, кликабельная ссылка). На копируемый текст это не влияет — в буфер всегда уходит обычный текст. Под полем показан счётчик символов с лимитом подписи к фото в Telegram (1024).

Автоматика и настройки (блок «Настройки текста», сохраняются на устройстве):

| Что | Как работает |
| --- | --- |
| Дата | По умолчанию подставляется **сегодняшняя** дата в формате «3 ноября, вт». Можно выключить авто и брать дату из поля «Основное». |
| Часовой пояс | При включении добавляется к дате: «· МСК». |
| Первый матч | Определяется автоматически по самому раннему времени, независимо от порядка ввода; показывается над полем текста. |
| Порядок матчей | По умолчанию список отсортирован по времени (первый = самый ранний); сортировку можно отключить, тогда сохраняется порядок карточек. |
| Ссылка на стрим | Один раз задаётся в настройках и подставляется во все посты. Если поле пустое — берётся «Ссылка на стрим» из «Основного». |
| Telegram-канал | Отдельное поле в «Основном». Не влияет на текст — только на футер постера «Итоги дня» (SVG-иконка + `t.me/…`). |
| Ручная правка | Итоговый текст редактируется прямо в поле. Пока правка активна, изменение данных не перезаписывает её — показывается предупреждение и кнопка «Собрать заново». |

Кнопка **«Скопировать текст»** использует `navigator.clipboard` с запасным способом для iOS Safari; дальше остаётся вставить подпись в Telegram вместе с картинкой.

## Интерфейс для телефона

На экранах ≤900 px редактор превращается в четыре раздела с **нижней панелью навигации**: «Данные», «Логотипы», «Картинка», «Текст». Переключатель типов поста доступен на всех экранах и сохраняет открытую вкладку. Панель учитывает `safe-area` iPhone, все кнопки и поля рассчитаны на палец (≥44 px), ввод не вызывает зум iOS (поля счёта и коэффициентов — текстовые с цифровой клавиатурой), блок «Основное» свёрнут по умолчанию, чтобы сразу были видны матчи. На десктопе сохраняется двухколоночный вид: слева данные, логотипы и панель текста, справа — закреплённая картинка с экспортом.

## Локальный запуск (ПК / ноутбук)

Нужны Python 3.12+ и Node.js 20+.

**Backend** (терминал 1):

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload --port 8000
```

Проверка: http://localhost:8000/api/health и документация http://localhost:8000/api/docs

**Frontend** (терминал 2):

```bash
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173 — на главной странице должен появиться блок «Сервер работает».

## Деплой на Render (с iPhone)

1. Создайте на GitHub репозиторий `stream-post` и загрузите в него содержимое проекта (папки `backend`, `frontend`, файлы `render.yaml`, `.gitignore`, `README.md`). Это можно сделать через приложение GitHub или сайт github.com в Safari («Add file → Upload files»).
2. В Render (dashboard.render.com): **New → Blueprint** → выберите репозиторий. Render прочитает `render.yaml` и создаст три ресурса: `stream-post-api`, `stream-post-web`, `stream-post-db`.
3. Дождитесь окончания деплоя. Откройте адрес `stream-post-web` — главная страница должна показать «Сервер работает».
4. Если у backend оказался адрес не `stream-post-api.onrender.com` (имя было занято), откройте `render.yaml`, замените адрес в блоке `routes → destination` на реальный и сделайте commit — Render передеплоит сайт.

Заметки:
- Бесплатный web service на Render «засыпает» без запросов, первый запрос после паузы может занять до минуты.
- Бесплатная база PostgreSQL на Render действует ограниченное время (около 30 дней), потом её нужно пересоздать или перейти на платный план.
- Переменные окружения backend: см. `backend/.env.example`.

## Принципы

- Код разделён по модулям: новая функция — новый файл в `api/routes` (backend) или `components`/`pages` (frontend).
- Все настройки — через переменные окружения, секреты в репозиторий не попадают (`.env` в `.gitignore`).
- Данные пользователя (черновик, логотипы) остаются на его устройстве и не отправляются на сервер.
